# Release bundle — 2026-08-11 (23:36)

Supersedes `iis-full-20260811-1740`. Deploy this one.

## What changed since the 1740 bundle

**Editing a country now works.** `UpsertCountryCommandValidator` demanded a phone code, but the
seeded world catalogue supplies one for Egypt only — 188 of 189 countries had none. The edit form
also pre-filled a bare `+`, which fails the format rule on its own. Between them, opening **Edit**
on any seeded country and pressing **Save** was guaranteed to fail with HTTP 400, which the panel
surfaced as a generic "Something went wrong".

The calling prefix is now optional, matching the rest of the system: the entity defaults it to
empty, the column has an empty default, and the list already rendered a dash for a missing one. The
format is still enforced when a prefix *is* supplied, and a bare `+` is stored as empty.

- `api\` — validator and handler fix
- `admin\` — the form no longer pre-fills `+` and no longer marks the field required
- `web\` — **unchanged** from the 1740 bundle (`index-BlCDLJc1.js` is byte-identical), so you can
  skip redeploying it if you already did

Verified by a 96-check regression suite over the whole platform, run green before this bundle was
cut, including three checks specifically for this fix (empty prefix saves, bare `+` normalises to
empty, malformed prefix still rejected).

## What this release contains

- **Reveal an order's password** — `GET /api/v1/admin/orders/{orderId}/password`, gated on the new
  `Orders.ViewPassword` permission. Registration also stores the generated password encrypted,
  alongside the existing hash. **Orders created before this release have nothing to reveal.**
- **SendGrid API key managed from the admin panel** — **Settings** page (`/settings`), gated on
  `Settings.View` / `Settings.Update`. Stored encrypted in `SiteSettings`, read per send, so
  rotating it needs no redeploy.
- **Country editing fixed** (above).
- **Schema**: one new nullable column, `Orders.PasswordSecret`.

## 🔴 Still required on the server

The Settings page stays disabled until the API has an encryption key. This is the outstanding item
from the last deploy, not something this bundle changes.

Generate one:

```powershell
$b = New-Object byte[] 32
[System.Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b)
[Convert]::ToBase64String($b)
```

Put it in **either** place — `web.config` wins if both are set:

| Where | Notes |
| --- | --- |
| `api\web.config` → `<environmentVariable name="Security__EncryptionKey" value="…" />` | Matches the existing deployment guide |
| `api\appsettings.Production.json` → `"Security": { "EncryptionKey": "…" }` | **Recommended.** Not in the repo, never generated by publish, excluded by the robocopy line below, so it survives every update. Template in `templates\`. |

**Back the value up** somewhere other than the server. Change it later and everything encrypted
under it becomes unreadable.

### While you are in that file

If the API `web.config` was overwritten by an earlier deploy, these went with it:

- **`Jwt__SigningKey`** — urgent. Without an override the API signs tokens with the placeholder
  committed to the repository, so anyone who can read the repo can forge an admin token.
- **`Storage__RootPath`** — without it, uploads are written inside the published site folder and
  the next `/MIR` deploy deletes them.
- `Cors__AllowedOrigins__N`, `App__WebUrl`, `App__AdminUrl`.

`api\` deliberately ships **without** a `web.config`, so a deploy can no longer overwrite yours.

## Deploy

### 1. Database — skip if you already ran these

Unchanged from the 0809 bundle and idempotent, so re-running is harmless.

```powershell
sqlcmd -S <server> -d VData_Prod -U <user> -P <password> -C -b -i "database\01-add-order-password-secret.sql"
sqlcmd -S <server> -d VData_Prod -U <user> -P <password> -C -b -i "database\02-new-permissions.sql"
```

Edit `@GrantToEmail` at the top of `02` first. `-b` returns a non-zero exit code on error.

> Assumes the database is at `20260802173703_AddAdminAttachedDocuments`. If it is further behind:
> `dotnet ef migrations script <from> <to> --idempotent`.

### 2. API and Admin

```powershell
Stop-WebAppPool -Name "<your api pool>"
robocopy "<bundle>\api"   E:\inetpub\DataVerification\api   /MIR /XF web.config appsettings.Production.json
Start-WebAppPool -Name "<your api pool>"

robocopy "<bundle>\admin" E:\inetpub\DataVerification\admin /MIR /XF web.config
```

`/XF web.config` on the **admin** line is load-bearing: the SPA `web.config` holds the rewrite rules
and is not part of the build, so without it `/MIR` deletes the file and deep links start 404ing.

### 3. Web — optional

Byte-identical to the last bundle. Only needed if you skipped that deploy:

```powershell
robocopy "<bundle>\web" E:\inetpub\DataVerification\web /MIR /XF web.config
```

Then **Ctrl+F5** once.

## After deploying

1. **Sign out and back in** — permissions are baked into the token at login.
2. Open **Lookups → Countries**, edit any country and save. It should succeed without touching the
   phone code.
3. Open **Settings**. Once the encryption key is in place the amber banner goes, and you can paste
   the SendGrid key.
4. Register a test order and confirm the credentials email arrives.

> Registration is rate-limited to **5 per 15 minutes per caller** (`RateLimiting:Registration`).
> Repeated testing returns HTTP 429 and the form simply fails. Worth reviewing whether that suits
> real applicants behind a shared office IP or carrier NAT.

## Rollback

Redeploy the previous release over `api\` and `admin\`. The new column is nullable and older builds
ignore it, so no schema rollback is needed. Older builds also ignore the stored SendGrid key and
fall back to `SendGrid__ApiKey` — make sure that is set before rolling back, or email stops.
